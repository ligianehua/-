# ru-ecom-product — 俄罗斯跨境电商商品卡片 Skill

## 你在做什么

把一份中文（或英文）产品资料，变成俄罗斯三大平台能直接用的商品卡片。
不是"翻译"，是"本地化 + 平台适配 + 合规 + 搜索优化"四件事一起做。

第一性原理：俄罗斯买家在平台搜索框里打的是**俄语口语词**，看的是**图上的大字**，
买不买取决于**参数是否按俄罗斯习惯写**（厘米、公斤、220 В、RU 尺码、逗号小数）。
翻译得再漂亮，标题超过 60 个字符 WB 直接截断，描述里出现"скидка"Ozon 直接驳回。

## 输入（Step 1）

用户会给你以下部分或全部内容，缺什么就按 `templates/intake.md` 追问，一次问完，不要挤牙膏：

| 字段 | 必填 | 说明 |
|---|---|---|
| 产品名称（中/英） | 是 | 原始名称、品牌、型号 |
| 产品图片 | 否 | 文件或 URL。能看图就看图，从图里提取可见卖点、颜色、配件；看不了就要求用户口述 |
| 产品视频 | 否 | 同上。有视频就产出俄语脚本 + 字幕 |
| 产品参数 | 是 | 尺寸、重量、材质、功率、容量、颜色、尺码、包装等 |
| 产品介绍 | 是 | 卖点、使用场景、目标人群 |
| 目标平台 | 否 | 默认三平台全出：Ozon、Wildberries、Яндекс Маркет |
| 类目 | 否 | 不给就自己判断，并在输出里标注你判断的 категория |
| 售价/成本 | 否 | 有的话在 `compliance.warnings` 里给定价提示 |

## 工作流

按顺序执行，每一步的产物都要落到最终 JSON（`templates/output.schema.json`）里。

### Step 0 · 归一化
1. 把所有参数转成俄罗斯度量与书写习惯（见 `references/russian-style.md`）：
   厘米/毫米/克/公斤/升/毫升，小数用逗号，千位用空格，温度 °C，电压 220 В / 50 Гц。
2. 服装鞋类：换算 RU 尺码（`references/russian-style.md` 的尺码表）。
3. 品牌名保留拉丁原文，不转写；型号保留原样。
4. 判断类目，读 `references/marketplaces.md` 找到对应平台的字段和限制。

### Step 1 · 看图看视频
- 有图：逐张写一句"图里能看到什么"（颜色、材质、接口、配件、使用场景）。这些是标题和图文文案的素材，也用来交叉核对参数（图里是 USB-C，参数写 Micro-USB，就要提出来）。
- 有视频：拆成镜头（时长、画面、要说的话），产出俄语旁白脚本 + SRT 字幕。
- 没图没视频：不要编造视觉细节，在 `infographic` 里只写文案，`image_ref` 留空。

### Step 2 · 俄语卡片（`ru.*`）
读 `references/russian-style.md` 和 `references/glossary.md`，产出：
1. **标题**：每个平台一个版本，严格按平台字数与结构（类型 + 品牌 + 型号 + 关键属性）。
2. **描述**：结构固定 —— 开头一句场景/痛点，"Преимущества"要点，"Характеристики"，"Комплектация"，"Гарантия и уход"。不要写平台禁用词。
3. **卖点要点（bullets）**：5–7 条，每条 ≤ 80 字符，名词开头，可直接上图。
4. **参数表（specs）**：name / value / unit 三列，name 用平台常用俄语属性名。
5. **平台属性映射（attributes）**：Ozon 与 WB 各自的字段名（见 `references/marketplaces.md`）。
6. **图文文案（infographic）**：6–8 张，每张一个 headline（≤ 5 个词）+ subline（≤ 12 个词）。第一张是主图，只写产品类型 + 一个最强卖点。
7. **FAQ**：3–5 条俄罗斯买家最可能问的问题及回答（尺寸合不合、能不能洗、保修、是否原装）。

### Step 3 · 关键词与标签（`keywords.*`）
读 `references/keywords.md`：
- 分三层：ВЧ（高频，1–3 个词）、СЧ（中频，带属性）、НЧ（长尾，带场景/人群）。
- 必须包含：西里尔转写变体（пауэрбанк / повербанк）、拉丁原词、常见错拼、同义词。
- 给出 `negative`（不要出现的词，避免被判违规或引流错误人群）。
- 给出 `hashtags`（Ozon 描述里可用的 #标签，≤ 10 个）。
- 明确标注来源：如果你没有接到 Wordstat / MPStats 等真实搜索数据，`keywords.source` 写 `"llm-estimate"`，并在最终回复里提醒用户用真实数据复核。**不要假装这是搜索量数据。**

### Step 4 · 合规（`compliance.*`）
读 `references/compliance.md`：
- 判断适用的 ТР ТС / ТР ЕАЭС 技术法规，给出需要"сертификат"还是"декларация"还是"отказное письмо"。
- 判断是否属于 Честный ЗНАК 强制标识类目。
- 生成俄语标签（этикетка）文本：名称、成分/材质、制造商、进口商、原产国、日期、ЕАС 标志位。
- 扫描广告法风险：最高级、绝对化、医疗功效、未证实的"оригинал"等。

### Step 5 · 校验
把输出 JSON 写到文件，跑：

```bash
python3 scripts/validate_card.py output.json
```

校验项：各平台标题/描述长度、禁用词、联系方式/URL、emoji、西里尔占比、关键词去重、卢布格式。
有 `ERROR` 必须改完再交付；`WARN` 在最终回复里逐条说明。

### Step 6 · 交付
- 主产物：`output.json`（符合 `templates/output.schema.json`）。
- 人类可读版：按 `templates/product-card.ru.md` 渲染一份 Markdown。
- 回复里用一段话说清楚：类目判断、合规红线、关键词数据来源、哪些字段需要用户补充。

## 硬规则

1. 平台字数限制是硬限制，超一个字符都算失败。见 `references/marketplaces.md`。
2. 描述和标题里禁止：联系方式、外链、其他平台名、促销词（скидка / акция / распродажа / хит / лучший / №1）、全大写、WB 标题禁 emoji。
3. 不确定的参数不要编。写 `уточняется` 并在 `qa.missing_fields` 里列出。
4. 医疗、儿童、食品、化妆品类目：合规段落必须写，且提示用户"没有证书别上架"。
5. 品牌名和型号不翻译、不转写。
6. 输出语言：卡片内容全俄语；给用户的说明用用户的语言。
