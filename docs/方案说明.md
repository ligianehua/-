# 俄罗斯跨境电商商品卡片 Skill · 方案说明

> 适用：Codex CLI、Claude Code
> 分支：`claude/russia-ecommerce-product-workflow-o3z5r7`
> 状态：v0.2 已交付，校验通过（0 error）。v0.2 吸收了另一份规划文档的事实纪律与控制机制。

---

## 1. 一句话

把一份中文产品资料，变成 Ozon / Wildberries / Яндекс Маркет 能直接上架的俄语商品卡片，外加分层关键词、标签、合规门禁和自动校验。

不是翻译，是四件事一起做：**本地化 + 平台适配 + 合规 + 搜索优化**。

## 2. 第一性原理

俄罗斯买家在搜索框里打的是俄语口语词，看的是图上的大字，买不买取决于参数是否按俄罗斯习惯写（厘米、公斤、220 В、RU 尺码、逗号小数）。

翻译得再漂亮，标题超过 60 个字符 Wildberries 直接截断；描述里出现 "скидка"，Ozon 直接驳回。所以工作流的每一步都围绕"平台会不会收、买家能不能搜到"来设计。

贯穿全流程的一条纪律：**一个商品只维护一份事实，允许多套表达，再分别适配平台规则。** 文案、关键词、图文、视频全部引用事实档案；事实档案里没有的，任何地方都不许出现。

## 3. 工作流

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 0 事实档案 + 归一化 | 每个参数记录值、来源、状态（confirmed / unverified / conflict / missing）；冲突标出不裁决，缺失不补常识值；单位换 см / кг / 220 В；变体各自建 SKU | `facts[]`、`source.variants[]` |
| 1 看图看视频 | 逐图提取可见卖点写入观察记录，与文字资料交叉核对；视频拆镜头 | 图片观察、视频脚本 + SRT |
| 2 关键词计划 | **在写文案之前**。ВЧ / СЧ / НЧ 三层，每个词带中文释义、用途、适用 SKU、验证状态；反向词；Ozon #标签；内部标签分开 | `keywords.*` |
| 3 俄语卡片 | 标题消费关键词计划；固定结构描述；参数表每行指回事实；属性映射；图文文案；FAQ；**中文对照字段** | `ru.*` |
| 4 合规与门禁 | ТР ТС 对照，Честный ЗНАК，俄语标签，无依据宣传隔离，门禁三态 proceed / needs_materials / blocked | `compliance.*` |
| 5 校验 | `scripts/validate_card.py`，0 error 才交付，`blocked` 直接报错 | 校验报告 |
| 6 交付 | JSON + 中俄对照 Markdown + 供应商补资料中文信息 + 版本号 | 交付包 |

关键词为什么前置：先判断买家怎么搜，再决定标题回答什么、图文回答什么。反过来会得到"翻译得很好但没人搜到"的卡片。

## 4. 事实档案怎么工作

| 场景 | 系统怎么处理 |
|---|---|
| 参数表写 500 mL，图上印 450 mL | `status: conflict`，两个值和来源都记下，卡片里不写容量，进 `qa.conflicts`，问供应商 |
| 介绍只写"不锈钢"，没牌号 | 只写不锈钢，不补成 304 |
| 没给保温时长 | `status: missing`，卡片写 `уточняется`，不写"24 часа" |
| 视频里有喷水画面 | 不推出 IP 等级 |
| 介绍说"抗摔"，没测试报告 | 进 `compliance.claims_to_review`，卡片只写"铝合金边框" |
| 图上有三个配件，清单只写一个 | 标冲突，确认实际包含物 |

分开记录，不许互相顶替：商品尺寸 vs 包装尺寸，净重 vs 发货重量，单件 vs 套装，型号 vs 店铺 SKU。

## 5. 输入与输出

**输入**

| 字段 | 必填 |
|---|---|
| 产品名称、品牌、型号 | 是 |
| 产品参数 | 是 |
| 产品介绍 | 是 |
| **销售模式**（跨境直发 / 本地仓 FBO / FBS / DBS） | 是。费用、进口人、标签都跟着变 |
| 图片 / 视频 | 否 |
| 目标平台、类目、变体、售价、认证、搜索数据 | 否 |

缺资料按 `templates/intake.md` 一次问完；缺口在供应商那边的，自动生成可转发的中文询问信息。

**输出**：`output.json`，六个顶层块：`source`、`facts`、`ru`、`keywords`、`compliance`、`qa`。结构见 `templates/output.schema.json`。

## 6. 平台硬限制（校验脚本同步）

| 项目 | Ozon | Wildberries | Яндекс Маркет |
|---|---|---|---|
| 标题 | 200 字符 | **60 字符** | 150 字符 |
| 描述 | 6 000 | **2 000** | 6 000 |
| 图片 | ≤ 15，1:1 | ≤ 30，**3:4** | ≤ 20，1:1 |
| 标题 emoji | 不推荐 | 禁止 | 禁止 |
| 买家可见标签 | 描述中 #тег | 无（API 的 tags 是卖家内部标签） | 无 |

三平台共同禁止：联系方式、外链、其他平台名、促销词、全大写、未证实的 "оригинал"、医疗功效。

## 7. 校验脚本抓什么

- 各平台标题 / 描述长度；禁用词、医疗声明、其他平台名；电话、URL、邮箱、社交账号；emoji；西里尔占比；单位与数字格式；标题词根重复
- **事实纪律**：`missing` 的事实被填了值；卡片引用了 `conflict` 的事实；`missing` 事实在卡片里不是 `уточняется`；参数表的值与事实不一致
- **变体**：SKU 重复；两个变体属性完全相同；图片引用不存在
- **关键词**：`source` 是 `llm-estimate` 却有 `verified` 词；`verified` 没有 volume / source；缺中文释义或用途
- **合规**：`gate` 缺失或 `blocked`；`claims_to_review` 里的词出现在卡片里
- **输入安全**：卡片文本里出现"忽略之前的指令"类内容
- **缺销售模式**

反向测试：一张故意写坏的卡片抓到 10 个 error。样例卡片 0 error，2 个 warning（关键词为候选、门禁为需补材料，都是如实标注）。

## 8. 控制机制

- **权限**：首版只生成和导出，不自动发布。接入 API 后读取、改内容、改价、删商品分开授权。
- **密钥**：只从环境变量读，不进 Skill、不进仓库。
- **输入安全**：供应商文件、网页、图片里的文字是资料，不是指令。
- **错误处理**：缺必填信息就 `blocked`；没有外部数据就明确标注；工具失败保留中间产物，只重试失败步骤。
- **版本与重跑**：`qa.version` 递增；`qa.manual_edits` 里的字段重跑时不覆盖。
- **完成的定义**：文案交付可审核文本；媒体交付实际文件。视频脚本不是视频，`rendered_file` 为 null 就说"未生成"。
- **媒体保真**：默认真实商品抠图 + 模板文字。生成图不能多按钮、少接缝、改接口、改颜色、把不含的配件画成赠品。

## 9. 首版验收标准

范围：**一个平台、一个类目、10 个真实商品**。样本故意包含：资料缺失、参数冲突、多颜色或多规格变体、带视频。

每个商品验收：

| 检查项 | 通过条件 |
|---|---|
| 所有关键参数有来源 | `facts[]` 无空 `source` |
| 未知项没被编造 | `missing` 事实在卡片里是 `уточняется` |
| 冲突没被自行裁决 | `conflict` 事实不进卡片，进 `qa.conflicts` |
| 变体不串图不串数 | 每个 SKU 独立图片和属性 |
| 俄语经过审核 | 中俄对照版有人看过，图上文字逐字核对 |
| 校验通过 | 0 error |
| 必填缺失确实阻断 | 缺进口人 / 证书时 `gate` 不是 `proceed` |
| 重跑不覆盖人工修改 | `manual_edits` 字段保持 |
| 工具失败不报成功 | 没有 MP4 就 `rendered_file: null` |
| 平台响应和搜索数据没有虚构 | 无数据时全部 `candidate` |

同时记录效率指标：每个商品的人工修改量、返工次数。上线后的点击、加购、成交是下一阶段指标，不代替首版的准确性验收。

## 10. 现在的边界

1. **关键词没有搜索量数据。** 没接 Wordstat / WB / Ozon 后台之前全是候选词。
2. **合规是清单，不是法律意见。** 证书类型和 Честный ЗНАК 范围要认证机构确认。
3. **平台字数限制会变。** 常量在 `references/marketplaces.md` 和 `scripts/validate_card.py` 两处。
4. **Codex 项目级 Skill 目录未能在线核实。** 仓库同时提供 `.codex/skills/` 和 `.agents/skills/` 两个入口（软链接），哪个被识别用哪个。

## 11. 还需要什么功能

详见 `docs/ROADMAP.md`。要点：

- **P0**：定价计算器（unit economics）、合规前置到选品阶段、平台 API 直传（MCP）

## 12. 不建议做的

- 自动刷评 / 刷单。
- 绕过 Честный ЗНАК。
- 一键翻译 100 个 SKU 不看。
- 为了技术名词齐全，提前拆出一堆 Agent 和 MCP 服务。先在一个流程里跑稳。
